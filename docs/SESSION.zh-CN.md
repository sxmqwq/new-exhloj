# 页面切换与登录异常

2.5.3 已修复两种可由本地测试确认的页面数据问题：失败的页面 JSON 请求不再被永久复用；切换页面、页面类型或账号后，旧请求不能把返回值写进新页面缓存。用户可以再次点击原操作重试，脚本不自动刷新或循环请求。

这不等于已确认或修复真实 HLOJ 服务端会话失效。当前没有使用实际 OJ 账号验证。脚本不保存或清除登录 Cookie，不调用退出接口，不修改站点的 UserContext，也不把 401/403 当作清除会话的指令。

## 对照定位

1. 在油猴中停用旧版和其他增强脚本，仅保留当前版本；核对设置面板版本。先在停用本脚本的状态下登录并切换相同页面，再启用当前脚本重复。
2. 打开浏览器开发者工具的 Network，开启 Preserve log，记录从哪个页面切到哪个页面，区分普通页面跳转、前进/后退和站点 PJAX。可以记录请求路径、HTTP 状态、返回内容类型、重定向目的路径以及时间。
3. 出现异常时在同一站点新开页面，确认原站用户菜单是否也显示未登录。如果原站仍然登录而仅某个增强功能失败，应先检查接口格式、页面权限或上下文刷新，不应直接判断为退出。
4. 若真实会话丢失，在 Application → Cookies 中本地比较 Cookie 的域、路径、过期时间及 SameSite/Secure 属性，检查第一个异常响应是否带有 Set-Cookie 或登录重定向。Cookie 值、请求 Cookie、Authorization、CSRF token 和 HAR 中的凭据无需提供给维护者。
5. 反馈时提供脚本版本、浏览器/油猴版本、切换路径、脚本停用/启用的对照结果，以及去掉查询敏感字段后的请求状态。设置面板“功能范围与故障信息”中的 `lastPageError` 可辅助判断。

401 只表示该请求未获授权；403 可能是权限不足；返回 HTML 可能是登录页，也可能是站点错误页。都应先在原站确认，不通过脚本重新登录、清 Cookie 或强制重定向。

## 自动检查范围

`npm run test:session` 启动仅监听 `127.0.0.1` 的 HTTP 服务器，通过 Chromium 的主机映射使用测试域名；浏览器只允许访问该本地服务器。测试会实际提交本地登录表单，获得 HttpOnly 会话 Cookie，再检查普通跳转、PJAX、前进/后退、错误恢复及异步响应隔离。账号和 Cookie 均为测试构造，不读取真实浏览器数据。

`tests/output/session-results.json` 记录版本、脚本 SHA-256、检查名和结果，不记录 Cookie 内容。它验证的是浏览器请求行为和脚本缓存隔离；不替代实际 Hydro/HLOJ 模板、服务器和 Tampermonkey 沙箱的兼容性验证。
